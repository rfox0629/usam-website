## Three findings that change Phase 5 scope

1. **V10 is mobile-only.** No desktop frame exists for any screen. The pilot must define desktop treatment by rule (same tokens/components, existing desktop layout preserved) — not invent desktop layouts.
2. **The Apps "+" FAB has a production purpose** (a shortcut menu to the More apps — Groups, Fruit, Library, Reports, Stewardship, Testimony Practice, Search More — at line 44651). V10 removed it because "no production action could be identified". Removing it is a product decision, not a visual one → add to the decision list (D12).
3. **Field rhythm pills and the Log-form "Coffee" default** depend on data/behavior that differs from production (`missionary_app.ts` line 174: "`missionary_field_people` has no equivalent" of `meeting_rhythm`; production default context is "In person"). Both are PL; the pilot keeps production defaults.
