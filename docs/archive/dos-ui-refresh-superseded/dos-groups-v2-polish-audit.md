# DOS Groups V2 Polish Audit

Status: Recommendations only. No new features implemented.

Product direction: Groups should feel like configuring a discipleship rhythm. Gatherings should be where ministry actually happens.

## Groups List

- Reduce explanatory copy above the list to one sentence or remove it if the cards are self-evident.
- Keep the primary action to one clear `New Group` entry point.
- Use compact group rows/cards with name, rhythm, next gathering, leader count, and status.
- Avoid repeating actions that also live in the detail view.

## Group Cards

- Make the group name, rhythm, and next gathering the visual hierarchy.
- Use role/status pills instead of explanatory labels.
- Keep card actions to `Open` plus one contextual secondary action when useful.
- Avoid large empty card interiors for groups with little data.

## Group Detail

- Lead with the current rhythm and next gathering.
- Move configuration/editing behind an obvious settings or edit action.
- Keep shared leadership visible but compact: Primary Leader, Co-Leaders, Helpers.
- Treat member management as a focused section, not a scattered set of repeated buttons.
- Keep gathering actions close to the next gathering or history list.

## Public Directory

- Reduce oversized hero treatment if it delays the actual group list.
- Keep public copy short and invitation-focused.
- Avoid exposing internal workflow language such as attendance, settings, leaders-only actions, or workspace concepts.
- Use consistent public cards with group name, audience, rhythm, short description, and `View Group`.

## Public Group Pages

- Keep the public page oriented around joining or requesting information.
- Preserve public-safe fields only: name, tagline, description, rhythm, location, scripture, and public join request form.
- Avoid internal labels like members, attendance, private prayer, workspace, person ids, or leader tooling.
- Reduce repeated calls to action if the same join form is present on the page.

## New Group Wizard

- Prefer a short template-first flow:
  - Type/template
  - Rhythm
  - Leader
  - Visibility
  - Review
- Collapse advanced settings until needed.
- Remove paragraphs that explain obvious form controls.
- Use field labels and concise helper text only where it prevents a real setup mistake.

## Cross-Cutting Cleanup

- Tighten vertical spacing in lists and cards.
- Keep button count low per surface.
- Favor compact rows, status pills, and drawers over large workflow cards.
- Keep typography within current DOS blue/white/soft-gray style.
- Do not introduce a separate Ryan/Dirk Groups product; use the beta allowlist and shared components.
